# RoleMesh 前端字段表（业务逻辑版）

## 一、项目（PROJECTS / MY_OWN_PROJECTS / MY_JOINED_PROJECTS）

三类列表共用同一套基础字段，仅个别字段按视角扩展，差异已在「说明」标注。

| 字段名            | 数据类型       | 业务逻辑说明                                                                                                                                                                                                                |
| -------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`         | string     | 项目名，同时是前端**跨实体关联键**：申请/邀请/会话/项目反查都用 `find(p=>p.name===...)` 靠它 join；发布必填。真实系统应改为主键 `id`，name 仅作展示                                                                                                                     |
| `type`         | string     | **项目类型**（发起方维度，单选、必选）：校园活动 / 科创项目 / 企业合作 / 学科竞赛 / 公益实践 / 创业孵化 / 其他。用于①`accentOf()` 决定卡片主色与左缘色条②卡片/详情「项目类型」标签。发布时单选，后端沿用原字段即可 |
| `domains`      | string[]   | **领域方向**（项目在做什么，多选、必选）：11 个预设值 + 自定义，如 `['AI / 机器学习','编程开发']`。用于①Mesh 筛选「领域方向」维度（`DIMS.domain`）②卡片/详情领域方向标签（`domainChips()`）。后端无该字段时 `domainsOf()` 按 skills/desc 关键词派生兜底，不会出现空标签 |
| `mode`         | string     | 合作模式（混合/线下团队/线上协作）。用于 Mesh 筛选「模式」维度与标签展示。发布时前端硬编码 `'线上协作'`（⚠️ 需后端改为可选参数）                                                                                                                                              |
| `stage`        | string（枚举） | 项目状态英文键：`idea`(想法) / `recruit`(招募中) / `doing`(进行中) / `sprint`(冲刺中) / `done`(已完结) / `teaming`(组队中) / `full`(组队完成)。**决定**：①卡片/详情 CSS 样式（`stageClass`）②详情页区块与按钮显隐③编辑弹窗可选项。其中 `full` 由「组队完成」副作用自动写入（不可手动选），`done` 前端未提供入口 |
| `stageText`    | string     | `stage` 的中文展示文案，与之一一对应，纯展示用途                                                                                                                                                                                          |
| `desc`         | string     | 项目简介，卡片与详情展示；发布必填、`maxlength=200`                                                                                                                                                                                     |
| `gaps`         | string[]   | 招募中的角色名数组。渲染「所需角色」chips（详情/匹配弹窗）；**入队副作用**：某角色招满（count≤0）时从 gaps 移除该角色名                                                                                                                                               |
| `urgent`       | string     | 急招角色名（= gaps 中某一项）。该角色在「成员要求」列表里显示红色急招点。发布时默认取 `gaps[0]`                                                                                                                                                              |
| `skills`       | string[]   | 项目技能标签。发布时从 `roles[].skills` 聚合去重而来；展示用                                                                                                                                                                               |
| `time`         | string     | 项目投入时间（如 `2-4小时/周`）。卡片「时间投入」与详情展示。⚠️ 项目级无空格、角色/画像级有空格，格式不统一                                                                                                                                                           |
| `count`        | number     | 项目总招募人数。卡片「招募人数」展示；**入队副作用** `count-1`，`count<=0` 触发组队完成                                                                                                                                                              |
| `roleDuty`     | string     | 角色职责一句话。发布时取 `roles[0].duty` 填充；详情展示                                                                                                                                                                                  |
| `members`      | object[]   | 已有成员 `{name,bio}`。渲染成员头像 chips；**入队副作用**同步去重新增成员                                                                                                                                                                      |
| `vibe`         | string     | 团队氛围。卡片/详情「氛围：xxx」展示；发布可空、空则默认 `'开放协作，高效沟通'`                                                                                                                                                                          |
| `match`        | number     | 匹配度 0–100 整数。**推荐排序依据**：首页取 match 前 3（`renderHomeHotProjects`）、Mesh 按 match 降序；显示「匹配度 xx%」；「最高匹配度」数字卡数据源。发布新项目同步到推荐列表时写死 `60`                                                                                         |
| `hot`          | boolean    | 是否热门。用于「热门优先」排序与首页「热门项目」区块                                                                                                                                                                                            |
| `roles`        | object[]   | 所需角色列表。渲染「成员要求」板块（每个角色对应技能要求）；**申请弹窗的角色选项来源**；发布必填 ≥1                                                                                                                                                                 |
| `matchRoles`   | object[]   | 匹配角色（仅 PROJECTS 推荐数据有）。详情页「最匹配角色」板块（仅 applicant 视角展示，取 match 最高的一条），子字段见下                                                                                                                                             |
| `reasons`      | object[]   | 推荐理由（仅 PROJECTS 有）。详情「为什么推荐你」展示；发布新项目同步时给空数组                                                                                                                                                                          |
| `teamFull`     | boolean    | 组队是否完成（仅 MY_OWN / MY_JOINED）。**决定**发起人详情页 Tab（无「匹配人才」）、操作栏（只留「项目群聊」）、是否隐藏招募要求；由「入队副作用」`count<=0 或 team.length>=count+1` 触发置 true                                                                                      |
| `team`         | object[]   | 已组队成员明细（仅 MY_OWN 组队完成项）。组队完成后展示成员 Talent Profile；**入队的真相源**（members 由 team 派生），子字段见下                                                                                                                                  |
| `joined`       | boolean    | 我是否已加入（仅 MY_JOINED）。决定详情页为参与者视角：展示「我的角色」、操作栏显示「进入群聊」                                                                                                                                                                  |
| `myRole`       | string     | 我担任的角色（仅 MY_JOINED）。详情「我的角色」区块展示；接受邀请时写入                                                                                                                                                                              |
| `applied`      | boolean    | 我是否已申请该项目（运行时）。**决定**卡片按钮态（「申请加入」vs「已申请 · 查看」）与详情操作栏；撤回申请后复位 false                                                                                                                                                    |
| `applyRole`    | string     | 已申请的角色名（运行时，随 `submitApply` 写入）；「已申请 · 查看」回显申请角色                                                                                                                                                                      |
| `applyProfile` | string     | 申请时使用的 Talent Profile 名（运行时）；回显申请所用画像                                                                                                                                                                                 |
| `applyExtra`   | string     | 申请附言（运行时）；回显申请补充信息                                                                                                                                                                                                    |

## 二、人才 / Talent Profile（TALENTS[].profile 与 MY_PROFILES 同构）

| 字段名      | 数据类型     | 业务逻辑说明                                                                         |
| -------- | -------- | ------------------------------------------------------------------------------ |
| `role`   | string   | 意向角色（`前端开发 / 全栈` 用 `/` 分隔）。申请时与项目角色匹配、参与匹配度计算；保存时把多角色 split 后 `join(' / ')` 归一 |
| `skills` | string[] | 技能/专长。**申请匹配度核心**：与项目角色 skills 求重合度，分三档提示；保存必填 ≥1                              |
| `exp`    | string   | 项目经历（整段文本）。画像展示；`maxlength=300`                                                |
| `field`  | string   | 感兴趣领域。画像展示，参与「方向契合」类匹配理由                                                       |
| `coop`   | string   | 协作偏好。画像展示                                                                      |
| `time`   | string   | 可投入时间（chip 单选）。画像展示 + 参与「时间契合」匹配理由                                             |

> TALENTS 顶层另有：`name`(string 姓名，人才→私聊/申请/画像反查的关联键)、`bio`(string 一句话定位)、`match`(number 匹配度，人才卡片排序)、`applied`(boolean 该人才是否已申请，**决定**发起人人才卡片的「同意/拒绝」按钮态)、`role`(string 申请角色)、`reasons`(object[] 同项目 reasons)。MY_PROFILES 顶层另有 `name`(string 画像名，如「我的主画像」，保存时按 name 覆盖)。

## 七、跨实体核对结论（供后端 DTO 定名参考）

1. **状态枚举两套并存**：项目用 `stage`(英文键)+`stageText`(中文文案)；申请用 `status`(中文 3 态：待查看/已通过/已拒绝)；邀请用 `status`(中文 3 态)。建议后端统一英文枚举 + 前端映射，或保留 `stage`/`stageText` 双字段约定。
2. **类型不一致点（重点）**：
   - `role`（Talent Profile 意向角色）在前端是 **string**（`/` 分隔），若契约要求 `string[]` 需后端拆分或前端改造。
   - `exp`（项目经历）在前端是 **string** 整段文本，非结构化数组。
   - `reasons` 是 **object[]**（`{label,text}`），`matchRoles[].reasons` 是 **string[]**，两者结构不同。
   - `time` 格式不统一：项目级 `2-4小时/周`（无空格） vs 角色/画像级 `2-4 小时/周`（有空格）。
3. **前端未实现、PRD 已定义的能力**：收藏项目/收藏夹（P1-3）、联系方式与可见性（P0-7）、多份 Talent Profile + 方向差异化模板（P0-6）——前端均无对应字段与数据。
4. **关联键约定**：前端大量用 `name`/`project`(项目名)、`applicant`(姓名) 关联，而非 ID；后端落地时以 ID 为主键，name 仅作冗余展示。
