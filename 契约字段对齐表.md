# RoleMesh 页面功能 ↔ docx 契约字段 对齐表

> 用途：把「页面上的东西」逐项对齐到《RoleMesh V0.1 匹配字段说明与对应关系》里的「契约字段（暗号）」。  
> 左列是页面，中列是契约暗号，右列是「要不要转换、怎么转」。  
> 标 ⚠️ 的 = 需要三方拍板的差异点；标「页面没做」= docx 已定义但前端还没采集/展示，契约先预留。  
> 说明：姓名、微信号、手机号、登录凭证、会员与支付信息**不进入算法**，本表只涉及会参与匹配的字段；身份/申请/邀请/消息单独放第四节。



---

## 一、人才侧（用户画像 Talent Profile）—— 匹配的「人」这一半

| 页面上的东西                | 页面现状                               | docx 契约字段                                                                   | 转换 / 差异                             |
| --------------------- | ---------------------------------- | --------------------------------------------------------------------------- | ----------------------------------- |
| 意向岗位（可填多个，逗号/顿号/斜杠分隔） | 自由文字                               | `intended_roles` : string[]（角色代码数组）                                         | ⚠️ 文字 → 角色代码数组，靠代码表转换               |
| 首选岗位                  | 页面没做                               | `primary_role` : string/null（必须属于 intended_roles）                           | 页面没做，需预留                            |
| 技能 / 专长（多条文字，逐行）      | 文字标签                               | `skills` : object[]（每项 = 技能代码 + 等级 + 来源）                                    | ⚠️ 文字 → 技能代码；等级 L1–L5 页面没采集，留空      |
| 项目经历                  | 整段文字                               | `experience_summary` : string（第一版保留文本）                                      | 一致，保留文本即可                           |
| 感兴趣领域                 | 自由文字                               | `domain_interests` : string[]（领域代码数组）+ `domain_preference_any` : boolean    | ⚠️ 文字 → 领域代码；「无偏好」标记页面没做            |
| 协作偏好                  | 自由文字                               | `collaboration_modes` : string[] + `collaboration_any` : boolean            | ⚠️ docx 要求「方式代码」和「自由描述」分开，页面混在一段文字里 |
| 可投入时间                 | 档位 chip（1-2 / 2-4 / 4-8 / 8+ 小时/周） | `availability_hours_per_week` : number（0–168）                               | ⚠️ 档位 → 数值，换算规则要定                   |
| 年级                    | 单选（大一~研究生）                         | `academic_year` : string/null（年级代码）                                         | ⚠️ 中文 → 年级代码                        |
| 专业                    | 自由文字                               | `major` : string/null（当前专业）+ `intended_major` : string/null（意向专业）           | 页面只有「专业」，<u>没有「意向专业」字段</u>          |
| 语言                    | 页面没做                               | `languages` : string[]（如 zh、en）                                             | 页面没做，需预留                            |
| 可开始时间                 | 页面没做                               | `available_from` : string/null + `availability_reported_at` : datetime/null | <u>页面没做，需预留</u>                     |
| 经验档位                  | 页面没做                               | `experience_level` : string/null                                            | docx 说「明确规则前不计分」，可暂不采集              |
| 画像标识 / 版本             | 页面没做                               | `profile_id` / `profile_version`                                            | 后端生成，前端只存不用                         |

## 二、岗位侧（发布项目 → 岗位）—— 匹配的「岗位」这一半

| 页面上的东西（大白话）     | 页面现状                    | docx 契约字段（暗号）                                                                                    | 转换 / 差异                               |
| --------------- | ----------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------- |
| 项目名称            | 文字                      | `project_id` : string + `name` : string（仅展示）                                                     | 页面没 ID，后端补；name 只展示不参与匹配              |
| 项目类型（单选，必选）     | 7 个预设 chip（校园活动 / 科创项目 / 企业合作 / 学科竞赛 / 公益实践 / 创业孵化 / 其他） | `project_type` : string                                                                          | ✅ 已拆出独立维度，沿用后端已有 `type` 字段，不新增表结构         |
| 领域方向（多选，必选）     | 11 个预设 chip + 自定义        | `project_domains` : string[]（领域代码数组）                                                             | ✅ 由原「类型」改名并收敛选项；页面字段 `domains` |
| 项目简介            | 文字                      | 无匹配字段（docx 不把它当匹配项，仅展示）                                                                          | ⚠️ 确认简介是否只走展示                         |
| 项目状态            | 4 态单选（想法/招募中/进行中/冲刺中）   | `recruitment_status` : open / paused / closed / full                                             | ⚠️ 两套枚举不对应，要做映射                       |
| 岗位名称            | 预设（算法/开发/设计/商科/文案）+ 自定义 | `role_code` : string（角色代码）+ `name` : string（展示）+ `role_id` : string                              | ⚠️ 岗位名 → 角色代码                         |
| 岗位职责            | 文字                      | `duty` : string                                                                                  | 一致                                    |
| 岗位技能要求（多条文字）    | 文字标签，不分主次               | `required_skills` : object[]（硬性）+ `preferred_skills` : object[]（加分）                              | ⚠️ 页面没分「硬性/加分」，要拆两套，且每项带最低等级          |
| 岗位招募人数          | 数字                      | `openings_remaining` : integer（剩余名额，≥0）                                                          | 页面填的是「招募总数」，剩余名额由后端算                  |
| 岗位期待时间投入        | 档位 chip                 | `min_hours_per_week` : number/null（硬性最低）+ `preferred_hours_per_week` : number/null（期望）           | ⚠️ 页面只有一档，docx 要「最低 + 期望」两档           |
| 岗位版本            | 页面没做                    | `role_version` : integer                                                                         | 后端生成                                  |
| 团队合作氛围          | 文字                      | 无匹配字段（不参与匹配）                                                                                     | ⚠️ 确认氛围不进算法                           |
| 团队成员（姓名 + 简介）   | 文字                      | 无匹配字段（仅展示/关联）                                                                                    | 不参与匹配                                 |
| ~~急招标记（红点/红字）~~ | 页面有---删除                | 无对应字段                                                                                            | ~~⚠️ 页面独有，需决定进不进契约~~                  |
| 合作模式            | 发布时写死「线上协作」             | `allowed_collaboration_modes` : string[] + `collaboration_is_required` : boolean                 | ⚠️ 页面没真正采集，要补「方式多选 + 是否硬性」            |
| 语言要求            | 页面没做                    | `required_languages` : string[] + `language_requirement_mode` : any/all + `language_is_required` | 页面没做，需预留                              |
| 年级限制            | 页面没做                    | `allowed_academic_years` : string[]（[] = 不限制）                                                    | 页面没做，需预留                              |
| 专业限制            | 页面没做                    | `allowed_major_codes` : string[]（默认 []，第一版不启用）                                                   | 页面没做，docx 建议第一版不启用                    |

## 三、匹配结果（页面显示 ← 算法返回）

| 页面显示（大白话）      | docx 契约字段（暗号）                                              | 转换 / 差异                   |
| -------------- | ---------------------------------------------------------- | ------------------------- |
| 匹配度百分比 0–100   | `match` : integer/null（0–100 规则分，非成团概率）                    | 只有「符合」才有正式分，其它为 null      |
| 是否符合硬条件        | `eligibility` : eligible / ineligible / needs_confirmation | ⚠️ 页面目前没做「待确认 / 不满足」这两种展示 |
| 推荐理由（标签 + 一句话） | `reasons` : object[]（每项 code + label + text）               | 前端照显示，不自己算                |
| 不满足的硬条件        | `unmet_requirements` : object[]（代码 + 说明）                   | ⚠️ 页面目前没展示                |
| 需要补充的信息        | `missing_fields` : string[]                                | ⚠️ 页面目前没做「补信息」引导          |
| 最匹配的岗位         | `role_id` + 该岗位 `match`                                    | 前端取最高分岗位展示                |
| 候选人才及其匹配度      | `match`（人才侧）                                               | 前端照显示                     |
| 计算版本 / 时间      | `algorithm_version` + `computed_at`                        | 后端返回，用于「结果是否过期」判断         |

## 四、不参与匹配、但要走接口的（身份 / 申请 / 邀请 / 消息）

> 这部分 docx 没给字段，需**祺定义**契约；均不进入算法。

| 页面上的东西                      | 说明                              |
| --------------------------- | ------------------------------- |
| 身份：姓名 / 年级 / 专业 / 头像        | 姓名只做展示与关联，不进算法；头像需改「文件上传返回 URL」 |
| 学校                          | 前端固定「某某大学」，未采集，需确认来源            |
| 申请：申请哪个岗位 / 用哪份画像 / 附言 / 状态 | 附言不参与匹配                         |
| 邀请：邀请某人担任某岗位 / 接受 / 婉拒      | —                               |
| 消息：会话 / 私聊 / 群聊 / 消息内容      | —                               |
| 收藏项目、联系方式与可见性（PRD 已定义）      | 页面还没做，后端可先预留                    |

## 五、前端自留（不进契约，也不发给算法）

- 筛选器当前勾选态（发起方 / 领域 / 模式 / 岗位）—— 只作为列表接口的查询参数，后端不「记住」勾选本身
- 排序方式（匹配度优先 / 热门优先）—— 同上，仅查询参数
- 搜索框正在输入的字
- 相对时间文案（「刚刚」「1 小时前」）—— 前端由时间戳换算
- emoji 图标、标题里的加粗文字 —— 前端自己拼
- 头像的本地预览图
- 卡片展开/折叠、弹窗开关
- 团队氛围没填时的默认文案

## 六、需要三方拍板的差异清单（按优先级）

1. **四张代码表**（技能 / 角色 / 领域 / 语言）—— 意提出，祺和婕对齐。这是所有「文字 → 代码」转换的前提。
2. **意向岗位**：自由文字 ↔ 角色代码数组，谁负责拆？前端拆还是后端拆？
3. **技能**：文字标签 ↔ 「技能代码 + 等级」，等级 L1–L5 页面没采集入口，第一版怎么填（留空 / 默认自评最低）？
4. **可投入时间**：档位（1-2/2-4/4-8/8+ 小时/周）↔ 数值，换算规则怎么定？
5. **协作偏好**：页面混在一段文字里 ↔ docx 要「方式代码 + 自由描述」分开，怎么拆？
6. **岗位技能**：页面不分主次 ↔ docx 要「硬性 + 加分」两套，发布表单要不要加「必会 / 加分」标注？
7. **岗位时间**：页面一档 ↔ docx「最低 + 期望」两档，要不要在发布时分开填？
8. **项目类型 / 领域方向**：~~页面「类型」混了「发起方」「领域」两个维度~~ —— 已解决：拆成「项目类型」（单选必选，沿用后端 `type`）与「领域方向」（多选必选，`domains: string[]`）。后端只需给 `domains` 留一个字段，其余不动。
9. **状态枚举**：页面项目 4 态 ↔ docx `open/paused/closed/full`，做一张映射。
10. **匹配状态展示**：页面没做「待确认 / 不满足硬条件」两种展示，要不要补。
11. **急招 / 热门 / 氛围**：页面有、docx 没有，确认是否进契约、是否影响排序。

## 附：docx 里各状态的含义（供映射时对齐）

| docx 概念                 | 取值                                         | 含义                                  |
| ----------------------- | ------------------------------------------ | ----------------------------------- |
| 硬条件状态                   | pass / fail / unknown                      | 已知满足 / 已知不满足 / 缺信息无法判断              |
| 整体 eligibility          | eligible / ineligible / needs_confirmation | 全 pass / 有 fail / 无 fail 但有 unknown |
| 招募状态 recruitment_status | open / paused / closed / full              | 开放 / 暂停 / 关闭 / 已满                   |
| 语言要求 mode               | any / all                                  | 会一种即可 / 全都需要                        |
