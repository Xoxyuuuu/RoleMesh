# RoleMesh 需后端接口的动态数据清单

> 目的：把前端 `index.html` 里的数据，区分为「写死的 mock 演示数据」和「必须由后端数据库/接口支撑的实时数据」，帮助后端同学确定接口清单。  
> 结论先行：前端所有全局数据变量，在真实系统里**都应由后端接口返回**；其中「用户操作会改变」的 16 个写操作，是必须落地后端接口的**实时变化数据**。

---

## 0. 先搞懂：`PROJECTS` 这些是什么？

`const PROJECTS = [...]`（index.html 第 1467 行）是**前端 mock（模拟）数据**——把几组示例对象直接写死在代码里，目的是在没有后端的情况下撑起页面演示。

在真实系统里，这些数据**不应该写死在代码里**，而是由后端数据库保存，通过 API 返回，前端用 `fetch` 拉取后再渲染。所以：

| 前端现状                              | 真实系统应改成                                                                       |
| --------------------------------- | ----------------------------------------------------------------------------- |
| `const PROJECTS = [ 6 个写死的项目对象 ]` | `const res = await fetch('/api/projects'); const PROJECTS = await res.json()` |
| 数据在代码里、刷新就回到初始值                   | 数据在后端数据库里、刷新后仍是用户真实数据                                                         |

**判断口诀**：

- `const` 声明的全局数组（PROJECTS / TALENTS / MY_PROFILES / MY_OWN / MY_JOINED / CONVERSATIONS / ACTIVITIES）→ 是**初始展示数据**，真实系统里对应**读接口（GET）**。
- `let` 声明、且会在函数里被 `unshift / push / filter / =` 修改的（MY_APPLICATIONS / MY_INVITATIONS / RECEIVED_APPLICATIONS / GENERAL_DYNAMICS）→ 是**实时变化数据**，对应**写接口（POST/PUT/DELETE）**。

## 一、读接口（页面加载时从后端拉取初始数据）

| `MY_INVITATIONS`              | 我收到的邀请            | `GET /api/me/invitations`                         | —               |

## 三、快速定位「实时变化数据」的方法

想自己核对哪些数据是实时变化的，用下面两条命令在 `index.html` 里搜即可：

1. **找写操作**：搜索 `.unshift( / .push( / = MY_ / = RECEIVED_ / = CONVERSATIONS`，命中处就是「用户操作会改数据」的地方，对应上表 16 个写接口。
2. **找读数据**：搜索 `^const ` 和 `^let `，所有全局数据常量就是「后端需要返回的数据」，对应第一节读接口。

> 简化判断：**只要这个数据会因为用户点一下按钮而变化、且刷新后应该保留，它就必须有后端接口**；反之，如果只是页面样式、筛选器当前选中态（如 `DIMS`、`currentSort`）这类纯前端 UI 状态，则不需要后端。
